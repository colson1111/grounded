Reading this report

A user picks one anchor object per profile. To unlock, they point the camera at it; the on-device MobileCLIP encoder embeds the frame and ranks all category prompts by cosine similarity. The unlock fires if the anchor is anywhere in the top 10 — there is no minimum-score gate, by design.

Recall @k
Of all the frames where the anchor really was in view, the share where the model put it in the top 10. High recall → the legit user gets in. TP / (TP + FN).
Recall @1
The stricter version: the anchor was the single best match, not just somewhere in the top 10.
Precision @1
Of all the frames where the model's single best guess was a given anchor, the share that really were that object. TP / (TP + FP), at rank 1.
Steal rate
The false-unlock risk stated directly: for anchor X, the share of non-X images that still carry X into the top 10 — a wrong object unlocking the profile. This, not precision, is the number that matters for a top-10 unlock with no threshold.
Decoy
A handheld or off-list object (mug, bottle, phone) that matches no category and should never unlock anything.

Method & caveats

Test images
Openverse image search per category (Creative Commons / public-domain), licenses recorded per file in images_manifest.jsonl.
Candidate filtering
Each category over-fetched, then ranked by an independent CLIP model (ViT-B-16 / laion2b) against the category vs. a background prompt set; only the top matches kept.
Steal rate
For anchor X: share of images whose true category is not X that still put X in the top 10.
The eval set is CLIP-filtered, so it skews toward clear, unambiguous photos — real-world recall runs a few points lower.
303 of 770 shipped categories are tested here (the common household / office / garage / vehicle set). The long tail is unmeasured.
top-k 10 with no score threshold maximizes recall at the cost of steal rate; adjacent objects (oven / microwave, sofa / loveseat) trade top-k slots freely.
